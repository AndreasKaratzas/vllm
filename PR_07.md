## What Reviewers Need To See

- The failing parameter IDs from Buildkite or local pytest.
- Whether the fix is a real kernel correction, a backend selection rule, or a
  tolerance update.
- For tolerance changes: max absolute error, max relative error, and why the
  tolerance is architecture-specific.
- For backend changes: which feature the old backend lacked, e.g. sinks or
  prefix/prefill support.

## Validation Commands

- `pytest -v -s tests/kernels/core`

## Weak Confidence

- Numeric-only changes without an error table are weak.
- Backend overrides should be feature-specific, not broad architecture folklore.
