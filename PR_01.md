# PR 01 - AMD Buildkite Topology, Gates, And Sharding

## Reviewer Summary

This PR should contain only `.buildkite/test-amd.yaml` changes. Its job is to
make the AMD matrix run meaningful work on the correct hardware and to split
jobs that were timing out. It should not include runtime code fixes.

The risky part is not the sharding itself; it is any removal of MI250 coverage.
Every removed MI250 job needs an explicit reason and replacement coverage on
MI300/MI325/MI355, or it should be moved to a separate CI policy discussion.

## Why These Changes Exist

- The original `V1 e2e (4 GPUs)` job was running the heavy EAGLE cases as one
  group and was hitting the 180-minute ceiling. Logs showed the Llama 4
  multimodal EAGLE variants dominating wall time, so the group is split into
  four explicit parts instead of a shell `case` inside one `%N` job.
- `Multi-Modal Models (Extended Generation 1)` and
  `Multi-Modal Processor (CPU)` are shardable workloads; the labels now show
  `%N` so the UI reflects that Buildkite is actually sharding the work.
- The MI250 removals are based on capability mismatch or dependency problems:
  MI250 should not be the place where FP8/FP4/AITER/NIXL-spec-decode paths are
  validated if equivalent coverage exists on MI300/MI325.

## Reviewer Questions We Must Answer

- Are any labels still missing `%N` even though they use `parallelism`?
