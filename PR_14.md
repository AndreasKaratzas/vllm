# PR 14 - Dataset, LM-Eval, And Hugging Face Compatibility

## Reviewer Summary

This PR should fix failures that happen before model execution because dataset
metadata or task loading is incompatible with the installed `datasets` /
`lm_eval` stack. It should not hide model accuracy failures.

## Failure Basis

The logs showed:

```text
ValueError: Feature type 'List' not found.
```

That occurred while `datasets` reconstructed cached dataset metadata, before
the vLLM model path was exercised. The right fix is either a narrow
compatibility shim or a dependency/cache strategy, not a model-output tolerance
change.

## Reviewer Questions We Must Answer

- Why is `vllm/utils/hf_datasets.py` the right place for the compatibility
  shim?
- Is the shim process-global, and could it affect unrelated dataset loads?
- Would pinning or clearing the dataset cache be safer?
- Does this fix only dataset loading, leaving accuracy assertions unchanged?

## Validation Commands

- Reproduce the `Feature type 'List' not found` load before the patch.
- Run the failing `V1 Sample + Logits` command after the patch.
- Run one LM-eval small-model command and one large-model command that reaches
  actual model execution.

## Weak Confidence

- Global monkeypatch-style dataset compatibility is weak. Prefer a local helper
  or explicit version pin if it is practical.
